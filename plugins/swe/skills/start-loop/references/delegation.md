# Delegation contract

Delegate when it reduces bulk context, supplies a useful independent view, or
lets genuinely independent work proceed safely. A simple task may stay with the
lead. Parallelize only work with isolated worktrees or disjoint ownership.

## Worker brief

Give a worker the smallest complete brief it needs:

1. The bounded objective and observable acceptance criteria.
2. Relevant approved requirements and canonical document links. Include full
   source text when it is necessary or the worker cannot read the source.
3. Useful paths and patterns as starting points, with exact file ownership for
   concurrent writes.
4. Scope boundaries, authority limits, applicable checks, and the route for a
   blocker or consequential decision.
5. A concise result contract: status, changed paths or artifacts, verification
   evidence, and unresolved concerns.

Do not require a worker to rediscover known context. Do not copy bulk logs or
file contents into its report when stable paths suffice.

## Evidence and follow-up

Worker reports are inputs, not final verification. The lead inspects the
result, resolves interactions, and runs the final applicable checks.

Continue or redispatch while new evidence supports a plausible correction.
When failures repeat, diagnose the cause before spending another agent turn.
Escalate only when progress needs a consequential decision, missing authority,
or unavailable capability. Do not use fixed retry counts, mandatory model
escalation, cache-warming calls, or token-accounting ceremony as substitutes
for judgment.
