# autopilot-stack

Applies when: a queue of PRs to build and verify with full autonomy, handed to the operator to land ("autopilot, don't merge", "stack them, don't ship", "build the stack, I'll land it"). PRs that depend on each other come here also when the user asks for the merge. Then step 3 lands them with ship-stack after the handoff.

Run autopilot-full, but do not merge before the handoff. After it, only step 3 merges. Every loop tick re-reads this file, so each tick sees the no-merge rule.

1-stack-only-on-dependency: A PR stacks only when it depends on another PR, and stacks stay shallow. This is the one exception to autopilot-full step 5. Each child's owner builds on its parent's branch, not on trunk, and rebases onto that branch in autopilot-full step 3. Subagents commit in their own worktrees and never push or open PRs. When every owner reports its code-ready commit, the coordinator rebases the unpushed branches into one line (root onto trunk, each child onto its parent branch), verifies the top branch, and runs one `gh stack link` (then updates and checks each PR body with `gh pr edit <n> --body-file <rendered>` and `pr_body.py check -`). Fall back to plain `gh pr create --draft --base <parent-branch>` only when `gh stack` is unavailable. (ship-pr, ship-stack)
2-stop-at-verified: In place of autopilot-full step 8, run autopilot-full step 6 on each PR at its head in the linked stack, so a child's checks include its parent's code. An owner commits each fix in its worktree on the lowest branch that owns the code, and the coordinator replays the branches above it and pushes the line. A new head on a lower PR restacks the PRs above it, and a PR whose `git patch-id` the restack leaves unchanged keeps its verdict. Stop when each PR is verified and green at its current head, then hand the PRs to the operator. After the handoff, nobody pushes without the operator's go. A merge request in the user's task is that go. (autopilot-full)
3-land-on-request: When the user's task asked for the merge, run ship-stack on the handed-off stack. Otherwise skip this step and leave the landing to the operator. (ship-stack)

Reply: as autopilot-full, but list each PR with its verdict in place of what merged, and what step 3 landed. (ketchup)
