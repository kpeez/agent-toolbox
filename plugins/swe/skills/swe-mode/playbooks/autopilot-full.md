# autopilot-full

Applies when: a queue of independent PRs to run to merged with full autonomy, one owner per PR ("autopilot this queue", "full autopilot").

You own the verdicts, never the PRs. One owner carries each PR from build to merge, and nothing merges until your swarm, which never wrote the code, has proven the code that lands.

A verdict covers one patch, and green CI covers one head. The patch-id rule in ship-stack can carry a lane's result, and every new head needs its own green CI. Each owner is a Claude Code cloud session or a worktree subagent (`swe:daedalus`), or a Codex cloud task. Owners open draft PRs per ship-pr; the owner marks its PR ready at merge through the ship-pr Land procedure. Use `gh` only.

1-honor-operator-gates: The grant covers only the queue's items. Items the operator names as theirs and PRs outside the queue stop at merge-ready. A request to state the plan is not a go.
2-spawn-owner-per-pr: Spawn one owner per PR. It builds, opens its PR early so CI and bots run alongside the work, proves the change on the real artifact, babysits to green, and merges once steps 6 and 8 clear it. (ship-pr, babysit-pr, prove-it-works)
3-report-code-ready-head: The code is ready only after the `writing` prose rules, a self-review of the diff, and no-comments. The owner then rebases onto current trunk, runs the repo's checks for the touched paths, and reports the code-ready head before self-proof. It reports every later head, and merge-ready once self-proof, CI, and babysit are done. Fix rounds stay on that base unless trunk conflicts or breaks CI. (writing, no-comments)
4-assume-the-session-dies: Each owner pushes soon after it starts, opens its decision log, and pushes after every unit worth keeping. Whoever spawns a subagent records its id, state, and a stuck-after runtime in the root's store. Owners force-push only their own branch, with `--force-with-lease` pinned to the SHA they last pushed or took over, and stop and report on any push they did not make. (log-decisions)
5-run-owners-in-parallel: Run owners in parallel off trunk, never stacked, so each PR lands on its own.
6-swarm-verify-once: Run a full swarm once, at the code-ready head. It reruns the gates, proves the load-bearing behavior live on the real surface with the project's verification skill or a named driver, and audits the diff. Another full swarm runs only for new behavior, a redesign, or a large new diff; a rebase, conflict resolution, or minor fix gets one verifier at the new head. No clean verdict without the live lane and your audit of the merge-ready receipts. (swarm, prove-it-works)
7-send-findings-to-owner: Send every proven finding, whatever a lane labeled it, to the owner in one fix-forward, with a red test across every site with the same defect. A defect trunk shows without the PR is recorded against trunk and does not gate the PR. Never push a fix yourself, because each branch has one writer. Replace a stuck owner instead.
8-merge-only-verified: Green CI alone never authorizes a merge. Merge prep rebases onto current trunk, reports the new head, and waits for green CI. Right before the merge, fetch trunk and ask whether its changes can affect the patch. Rebase and wait for CI on a conflict, a file both sides changed, or a change to which checks run. Run the patch's checks on the merge result when trunk changed a caller or a dependency of the patch. A lockfile both sides changed needs no rebase when a frozen install passes on the merge result. Before a third rebase past merge prep, hold and report to the root. (ship-pr, ship-stack)
9-countersign-loosened-gates: Anything that loosens a gate, such as a raised budget or an allowlist entry, needs a verifier's proof and your fresh countersign. A disabled or soft-failed check always comes out. Never give or bypass an approval the forge enforces.
10-arm-audit-loop: On the operator's go, arm Claude Code `/loop 1h` until no delegated work is left (in Codex, rerun the audit by hand). Each tick re-reads this playbook, fixes drift through the owner, probes every agent down to the leaf lanes by side effects, and replaces a stuck agent at once. A tick that changed something for the operator catches them up; a tick that changed nothing stays quiet. (ketchup)
11-stand-down-on-stop: On the operator's stop, send every owner a zero-writes order. Each reports where it stands and keeps its brief until the operator releases it.

Reply: catch the operator up, covering each PR's state and verdict, what merged, countersigns and why, and open operator gates, with links to each PR and each decision log. (ketchup)
