# Agent rule enforcers

This table pairs each rule that stops a repeated agent mistake with what
enforces it. The `correct` skill in `plugins/swe` maintains it. Each row names
the past mistakes, the enforcer's path, and the command that runs it.

| Rule | Past mistakes | Level | Enforcer | Command |
|---|---|---|---|---|
| A plugin never names another plugin's skill, agent, or playbook | swe `hillclimb-metric` handed its loop to `lab:autoresearch`; swe `testing-code`, `swe-mode`, and `figure-it-out` named `lab:autoresearch`; lab `making-plots` named `swe:testing-code`; the shared `go-deeper` used swe's `interview-user` "when it is installed" | check | `.github/scripts/plugin_isolation.py`, run by `.github/workflows/checks.yml` | `uv run .github/scripts/plugin_isolation.py` |
| No plugin manifest or catalog entry sets `version`, so Claude Code updates on each commit | 93 commits shipped new plugin content under a version `main` had already shipped, such as `c9016d5` (llmos stayed 1.0.1); 4 version collisions, such as `fed1c56` (swe 1.21.24 set by two PRs) | architecture + check | `.github/scripts/manifest_versions.py`, run by `.github/workflows/checks.yml` | `uv run .github/scripts/manifest_versions.py` |
| A PR body is the filled `ship-pr` template and never names the requester or the chat | `## Why` sections and requester attribution in #207, #212, and PRs in other repos | architecture + check | `plugins/swe/skills/ship-pr/scripts/pr_body.ts` (`render` builds the body from `templates/pr-body.md`), the swe `PreToolUse` hook in `plugins/swe/hooks/hooks.json`, and `.github/workflows/pr-body.yml` | `bun plugins/swe/skills/ship-pr/scripts/pr_body.ts check body.md` |
| Dependent PRs in a `gh-stack` repo publish with `gh stack link` or `gh stack submit`, not hand-chained `gh pr create --base` | 30 dependent PRs opened with hand-set `--base` and no `gh stack link`, leaving GitHub without a stack | check | `plugins/swe/skills/ship-pr/scripts/pr_body.ts` (`hook`), run by the swe `PreToolUse` hook in `plugins/swe/hooks/hooks.json` | `bun test plugins/swe/skills/ship-pr/scripts/tests` |
| The eval facet map matches the skill sources, so the evals see each workflow change | the swe router (#157, now `swe-mode`) landed with no `swe-mode` eval case; `lab-mode` (#222) landed with cases that check only the router load | check | `evals/skills/facets.py`, run by `.github/workflows/checks.yml` | `uv run evals/skills/facets.py check` (fix with `write`) |
| swe prose names model roles (strongest, mid-tier, fastest), never a model name; only `plugins/*/agents/*` pin a model | `swarm`, `figure-it-out`, `recall`, and two swe docs named `opus`, `sonnet`, and `haiku` | check | the "Skills name model roles" step in `.github/workflows/checks.yml` | `rg -n -w -i 'opus\|sonnet\|haiku' plugins --glob '!plugins/*/agents/*'` (prints nothing; the step runs the same search with `grep`) |
